int sum = 0;
for (int i = 0; i < n; i++) {   // Loop A
    sum = sum + a[i];
}
for (int j = 0; j < n; j++) {   // Loop B
    sum = sum + a[j];
}

Key rule: Sequential (not nested) loops ADD their complexities

  • Loop A runs n times → O(n)
  • Loop B runs n times → O(n)
  • Total = O(n) + O(n) = O(2n)
  • Drop the constant 2 → O(n)
Why drop constants? Big O describes growth rate as n → ∞. Whether you do 2n or 100n operations, the shape of the curve is the same — linear. So we simplify to O(n).
Answer: O(n)
Two sequential loops each O(n) → O(n) + O(n) = O(2n) → drop constant → O(n). Time: O(n). Space: O(1) — only variables sum, i, j.

For 3 marks write:

"Loop A iterates n times [1 mark]. Loop B independently iterates n times [1 mark]. Combined: O(n) + O(n) = O(2n) = O(n) after dropping the constant [1 mark]."

○ O(n²) — because there are two loops
○ O(n) — they add, giving O(2n), and constants are dropped
○ O(2) — two loops, constant time

Big O — Nested Loop (logarithmic inner)
Determine the Big O expression for this code excerpt
[3 marks]
⌄
📖 Teach Me
✅ Answer
🧠 Quiz
int prod = 1;
for (int i = 1; i < n; i++) {          // Outer: i=1,2,3... → runs n times → O(n)
    for (int j = 1; j < n; j = j * 3) { // Inner: j=1,3,9,27... → runs log₃(n) times
        prod = prod * j;
    }
}

The critical insight: j = j * 3

When a loop variable multiplies each iteration, it grows exponentially — so it reaches n in far fewer steps.
  • j = 1, 3, 9, 27, 81... After k steps, j = 3^k
  • Loop ends when 3^k ≥ n → k = log₃(n)
  • Inner loop = O(log n)
  • Outer loop = O(n)
Nested loops MULTIPLY: O(n) × O(log n) = O(n log n)
LoopVariableStepComplexity
Outeri+++1 each timeO(n)
Innerj*=3×3 each timeO(log n)
Combined—NestedO(n log n)
Answer: O(n log n)
Outer loop: O(n). Inner loop j = j*3 means j grows as powers of 3 → runs log₃(n) times → O(log n). Nested = O(n) × O(log n) = O(n log n).
A loop runs with j = j * 3 starting at j=1. How many iterations until j ≥ n?
○ n iterations
○ log₃(n) iterations — because 3^k = n when k = log₃(n)
○ n/3 iterations
○ n² iterations

Big O — Nested Loop (step-3 outer)
Determine the Big O expression for this code excerpt
[3 marks]
⌄

✅ Answer

int sum = 0;
for (i=0; i<=n-1; i+=3) {    // i=0,3,6,9... → runs n/3 times
    for (j=n-1; j>0; j--) {     // j starts at n-1, decrements to 1 → n-1 times ≈ n

    }
}

Outer loop: i += 3 (not i++)

i goes: 0, 3, 6, 9 ... n-1. That's n/3 iterations. But n/3 = O(n) because constants are dropped.

Inner loop: j-- (counts down from n)

j goes from n-1 down to 1 → that's n-1 ≈ n iterations → O(n)

Nested = multiply

O(n/3) × O(n) = O(n²/3) → drop constant 1/3 → O(n²)
Exam trap: Students write O(n/3 × n) = O(n²/3). That's correct calculation but the final answer must drop the constant → O(n²)
Answer: O(n²)
Outer: i+=3 → n/3 iterations = O(n). Inner: j-- from n-1 to 0 → O(n). Nested: O(n) × O(n) = O(n²).
If outer loop does n/3 iterations and inner loop does n iterations (nested), what is the Big O?
○ O(n/3) — because the outer is divided by 3
○ O(n log n)
○ O(n²) — n/3 × n = n²/3, drop the constant
○ O(3n²)

The recursive factorial formula

factorial(n) = 1    if n = 0 or n = 1
factorial(n) = n × factorial(n-1)    if n > 1

What happens when you call factorial(5)?

Each call suspends, creates a stack frame in memory, and waits for the next call to return. The stack grows until the base case, then unwinds.
Stack frame = a block of memory that holds the method's local variables (n) and where to return when done. Like a bookmark inside a book — you pause here and go deeper.

Phase 1: Winding down (building the stack)

factorial(5) — n=5, calls factorial(4), waits
factorial(4) — n=4, calls factorial(3), waits
factorial(3) — n=3, calls factorial(2), waits
factorial(2) — n=2, calls factorial(1), waits
factorial(1) — n=1, BASE CASE — returns 1 ✓
↑ All 5 frames in memory simultaneously = O(n) space

Phase 2: Unwinding (returning values)

Frame returnsReturns valueRunning product
factorial(1)11
factorial(2)2 × 1 = 22
factorial(3)3 × 2 = 66
factorial(4)4 × 6 = 2424
factorial(5)5 × 24 = 120120 ✓
 
/**
 * Time:  O(n)  — makes exactly n recursive calls
 * Space: O(n)  — n stack frames live in memory simultaneously
 */
public static int factorial(int n) {
    if (n == 0 || n == 1) return 1;   // base case
    return n * factorial(n - 1);          // recursive case
}
Time Complexity O(n): factorial(n) makes exactly n recursive calls — factorial(n), factorial(n-1), ... factorial(1). Each call does exactly 1 multiplication. Total operations = n → O(n).
Space Complexity O(n): Each call pushes a new stack frame onto the call stack. At peak depth, all n frames exist simultaneously. Stack frame holds: local variable n, return address. Total memory used grows with n → O(n). This is the hidden cost of recursion.
Risk: For large n (e.g. 10,000), the call stack overflows → StackOverflowError. Iterative factorial has O(1) space and no overflow risk.
For factorial(5), how many stack frames are held in memory at peak (before any return)?
○ 1 — only the current frame
○ 4 — n-1 frames
○ 5 — frames for factorial(5) down to factorial(1) all waiting simultaneously
○ 25 — n² frames

VersionTimeSpaceWhy?

Same time, different space. Both do n multiplications. But iterative only ever uses variables prod and i — fixed regardless of n. Recursive creates a new frame for every n.
Recursive Factorial:
Time O(n) — n recursive calls, each performing one multiplication.
Space O(n) — n stack frames held simultaneously at peak recursion depth.

Iterative Factorial:
Time O(n) — loop runs n times, one multiplication per iteration.
Space O(1) — only variables prod and i regardless of n; no call stack growth.

○ O(n) — each recursive call creates a stack frame; n frames exist simultaneously
○ O(n²) — nested call overhead
○ O(log n) — stack shrinks by half each time

  • Continue until sorted

Count the steps

Bubble sort has two nested loops. Outer runs n-1 passes. Inner runs n-1 comparisons per pass.
Total comparisons = (n-1) × (n-1) = n² - 2n + 1

Simplify with Big O rules

Drop lower-order terms: n² - 2n + 1 → drop 2n and 1 → n² → O(n²)
CaseWhen?Complexity
BestAlready sorted (optimised version)O(n)
AverageRandom inputO(n²)
WorstReverse sortedO(n²)
Space complexity: O(1) — only a temp variable for swapping. No extra array needed.
Time: O(n²) — Two nested loops each running n-1 times. Total steps = (n-1)² = n²-2n+1 → O(n²) after dropping lower-order terms.

Space: O(1) — Only 3 variables (i, j, temp). Fixed regardless of n.

Best case O(n) possible with optimised version that stops early if no swaps in a pass.
What is the space complexity of Bubble Sort and why?
○ O(n) — needs a copy of the array
○ O(1) — sorts in-place using only a temp variable, no extra memory proportional to n
○ O(n²) — matches time complexity
○ O(log n)

Quick Sort — Divide and Conquer

  • Step 1: Choose a pivot (usually first, last, or middle element)
  • Step 2: Partition — move all elements < pivot to its left, all > pivot to its right
  • Step 3: Pivot is now in its final position — never moves again
  • Step 4: Recursively sort left sub-array and right sub-array
Key insight: After partitioning, the pivot is in its exact correct sorted position. Quick Sort is efficient because each partition reduces the problem size.
Note on this paper: The question doesn't specify pivot choice. Using first element as pivot is the most common default. If your lecturer taught a different method, use that — show your method clearly and you get the marks.

What is a Heap?

A max-heap is a binary tree where every parent is ≥ both its children. The root is always the maximum element. Heap Sort uses an array to represent the heap — no actual tree is created.

Array → Heap mapping (0-indexed)

For element at index i:
  • Left child = index 2i + 1
  • Right child = index 2i + 2
  • Parent = floor((i-1)/2)

Two phases of Heap Sort

  • Phase 1 — Build Max-Heap: Rearrange array so it satisfies max-heap property (heapify from last non-leaf down to root)
  • Phase 2 — Extract Max Repeatedly: Swap root (max) with last element, reduce heap size by 1, heapify root to restore max-heap, repeat
Heapify: Given a node, if it's smaller than either child, swap it with the larger child. Repeat downward until heap property is restored. This is the core operation.
Why this works: After extracting the max to the end of the array each time, sorted elements accumulate at the right — just like Bubble Sort, but much faster!

Why Heap Sort is always O(n log n)

  • Building the heap: O(n) — can be proven mathematically
  • Each extraction: O(log n) — heapify goes from root to leaf, tree height = log n
  • n extractions × O(log n) each = O(n log n)
CaseTimeWhy?
BestO(n log n)Same structure regardless of input
AverageO(n log n)Always n extractions × log n heapify
WorstO(n log n)No worst case — guaranteed!
Heap Sort's great advantage: Unlike Quick Sort, it has no O(n²) worst case. It's guaranteed O(n log n) regardless of input. Space O(1) — sorts in-place.
Comparison with other sorts:
Bubble Sort: O(n²) time / O(1) space
Quick Sort: O(n log n) avg / O(n²) worst
Heap Sort: O(n log n) always / O(1) space ← best of both worlds
Time: O(n log n) — all cases
Phase 1 (Build heap): O(n). Phase 2 (n extractions each requiring heapify): n × O(log n) = O(n log n). Total: O(n) + O(n log n) = O(n log n).

Space: O(1) — Heap Sort is in-place. No auxiliary array needed. Only a few variables for swapping.

Key advantage over Quick Sort: No worst-case O(n²). Performance is consistent regardless of input order.
What is Heap Sort's worst-case time complexity?
○ O(n²) — like Bubble Sort
○ O(n²) — like Quick Sort's worst case
○ O(n log n) — guaranteed, same as best and average case
○ O(n) — it only needs one pass
