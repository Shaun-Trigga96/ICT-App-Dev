QUESTION 1 (20 marks) – Factorial
1.1 Recursive trace (8 marks)
Trace for n=5:
factorial(5) → 5 * factorial(4)
factorial(4) → 4 * factorial(3)
factorial(3) → 3 * factorial(2)
factorial(2) → 2 * factorial(1)
factorial(1) → 1 (base case)
Unwind: 2*1=2, 3*2=6, 4*6=24, 5*24=120. Call stack depth = 5.
Each call pushes a frame; returns multiply backwards.
1.2 Iterative trace (6 marks)
Loop algorithm: result = 1; for i=2 to n: result *= i.
n=5:
i=2 → result=2
i=3 → result=6
i=4 → result=24
i=5 → result=120. Single pass, no extra call overhead.
1.3 Complexity comparison & real-world (6 marks)
Time complexity: Both O(n).
Space complexity: Recursive O(n) (call stack), Iterative O(1).
Preferable: Iterative, because recursion risks stack overflow for large n (e.g., n=10^5) and uses more memory. Recursive is elegant for mathematical definition but not production-friendly for large inputs.
QUESTION 2 (15 marks) – Big-O Analysis
2.1 (5 marks)
Two sequential O(n) loops → O(n + n) = O(n).
2.2 (5 marks)
Outer loop i=1..n-1. Inner loop j starts at i, doubles each time → O(log₂(n/i)) ≈ O(log n). Sum over i gives O(n log n). O(n log n).
2.3 (5 marks)
Outer loop runs ~n/3 iterations = O(n). Inner loop runs n-1 iterations = O(n). Nested → O(n²).
QUESTION 3 (35 marks) – Sorting Algorithms
3.1 QuickSort (12 marks)
Principle: Divide & conquer – pick pivot, partition so left < pivot ≤ right, recursively sort subarrays.
Trace {90,23,5,109,12} (pivot=12, Lomuto):
Initial: [90,23,5,109,12] → partition: i=-1; j=0 (90>12) skip; j=1(23>12) skip; j=2(5<12) i++ swap 90↔5 → [5,23,90,109,12]; j=3(109>12) skip; place pivot at i+1=1 → swap 23↔12 → [5,12,90,109,23]. Left [5] sorted; right [90,109,23] recursively pivot=23 → etc.
Complexities: Best O(n log n), Average O(n log n), Worst O(n²) (picked smallest/largest pivot).
3.2 HeapSort (15 marks)
Principle: Build max-heap from array → repeatedly swap root (max) with last element, heapify reduced heap.
Heapify {90,23,5,109,12}:
Index1 (23) children 109,12 → swap 23↔109 → [90,109,5,23,12].
Index0 (90) children 109,5 → swap 90↔109 → [109,90,5,23,12].
Sorting steps: swap 109 with last (12) → heapify root 12 → [90,12,5,23,109] → swap 90 with 23 → heapify → ... final sorted [5,12,23,90,109].
Complexity: Build heap O(n), each extract O(log n) → total O(n log n) worst/average/best.
3.3 Bubble Sort (8 marks)
Pass 1: (90,23)→swap [23,90,5,109,12]; (90,5)→swap [23,5,90,109,12]; (90,109) no swap; (109,12)→swap [23,5,90,12,109]
Pass 2: (23,5)→swap [5,23,90,12,109]; (23,90) no swap; (90,12)→swap [5,23,12,90,109]; (90,109) no swap.
Complexities: Worst & average O(n²), Best O(n) (already sorted with early termination flag).
QUESTION 4 (15 marks) – Queue (Array/Circular)
4.1 enqueue (4 marks) 
void enqueue(int val) {
    if (isFull()) throw new RuntimeException("Full");
    rear = (rear + 1) % CAPACITY;
    arr[rear] = val;
    if (isEmpty()) front = rear;
}
4.2 dequeue (4 marks) 
int dequeue() {
    if (isEmpty()) throw new RuntimeException("Empty");
    int val = arr[front];
    if (front == rear) front = rear = -1;
    else front = (front + 1) % CAPACITY;
    return val;
}
4.3 isEmpty (3 marks)
return front == -1; (or front == -1 && rear == -1).
4.4 peek (4 marks)
if (!isEmpty()) return arr[front]; else throw exception.
QUESTION 5 (15 marks) – Algorithm Fundamentals
5.1 Definition (2 marks)
An algorithm is a finite, unambiguous sequence of well-defined steps to solve a problem or perform a computation.
5.2 Characteristics (4 marks)
Finiteness, Definiteness, Input, Output, Effectiveness. (any four)
5.3 Time vs Space (5 marks)
Time complexity: number of operations vs input size.
Space complexity: extra memory required.
Example: Memoized Fibonacci – O(n) time, O(n) space due to array. Counting sort O(n+k) time but O(k) extra space.
5.4 QuickSort worst-case & avoidance (4 marks)
Worst-case scenario: Pivot always the smallest or largest element (e.g., sorted array and pivot chosen as first/last). Results in O(n²).
Avoidance: Random pivot selection or median-of-three pivot gives O(n log n) expected.
