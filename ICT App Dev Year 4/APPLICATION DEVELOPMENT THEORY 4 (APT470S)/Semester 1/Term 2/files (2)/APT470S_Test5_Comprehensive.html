1.4 Encapsulation definition? a) Hiding internal implementation details and exposing only necessary interfaces
1.5 Shows users interacting with system features? d) Use case diagram
1.6 Primary purpose of prototyping? b) To explore requirements and design options before full development
1.7 Integrating and testing code multiple times per day? c) Continuous integration
1.8 Burndown chart tracks? c) Remaining work versus time in a sprint
1.9 Agile values working software over documentation? TRUE
1.10 Acceptance testing by dev team with simulated data? FALSE — acceptance testing is done by the customer/client using real data
1.11 Software entropy means? b) The tendency of software to become increasingly disordered and harder to maintain over time
1.12 'Include' relationship in use cases? a) A use case that is always performed as part of another use case
1.13 Scrum Master manages product backlog and priorities? FALSE — the Product Owner manages the product backlog and priorities; the Scrum Master facilitates the process
1.14 Quality model with 6 characteristics? b) ISO/IEC 9126
1.15 Main benefit of TDD? c) Encourages writing tests before code, improving design and catching defects early
2.1 Best process model for SmartCity IoT system? Recommended: Agile (Scrum). Justification: (1) Partially defined, evolving requirements → agile handles change better than waterfall. (2) Expanding sensor network → incremental delivery allows the system to grow with the city. (3) Real-time IoT complexity → iterative testing each sprint catches integration issues early. Alternative acceptable: Incremental development (similar justification). [3 marks recommendation+justification, 3 marks linking to project challenges, 3 marks depth of argument]
2.2 Sprint review vs sprint retrospective? Sprint Review: external-facing; team demonstrates working software to stakeholders (city officials); stakeholders provide feedback; product backlog updated. Contributes to product improvement. Sprint Retrospective: internal-facing; team reflects on HOW they worked (process, tools, communication); identifies what went well and what to improve; agrees on actions for next sprint. Contributes to team performance improvement. Key distinction: review = product; retrospective = process/team. [3 marks per ceremony correctly distinguished]
3.1 Use case diagram for hospital admission system? Actors: Patient, Receptionist, Doctor, Nurse, Billing System (external). Use cases (min 6): Register Patient, Allocate Room, Record Vital Signs, Generate Invoice, Discharge Patient, View Patient Records, Update Medical Notes, Process Payment. Include example: 'Register Patient' includes 'Verify Insurance'. Extend example: 'Allocate Room' extends 'Register Patient' (only if room needed). [1 mark per actor correctly identified (max 5), 1 mark per use case (max 6), 1.5 marks for include/extend relationship correctly described = 9 marks]
3.2 Two non-functional requirements for hospital system? (1) Data Privacy / Security (POPIA/HIPAA compliance) — patient data must be encrypted at rest (AES-256) and in transit (TLS). Access must be role-based. Verified by: penetration testing, security audit, data access log review. (2) Availability / Reliability (24/7 operation) — system must have ≥99.95% uptime (< 4.4 hours downtime/year). Verified by: load testing, failover testing, monitoring dashboards showing uptime metrics over 90 days. [3 marks each: 1 requirement stated, 1 explanation linked to context, 1 verification method]
