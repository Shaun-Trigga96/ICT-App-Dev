2.1 Waterfall suitability for TechHealth? Challenges: Waterfall requires complete, stable requirements upfront; TechHealth's evolving requirements make this impossible. Changes mid-project are costly and difficult. Benefits: Provides clear structure, documentation, and milestones. Suitable only if requirements could be fully defined. Overall: Waterfall is NOT suitable; an agile/iterative model is more appropriate. [3 marks challenges, 3 marks benefits, 3 marks overall evaluation]
2.2 XP framework activities for CRM? Any two: (1) Planning — XP uses release planning and iteration planning; user stories replace heavy documentation, enabling the team to respond to client feedback quickly. (2) Design — Simple design (YAGNI principle); CRC cards reduce over-engineering. (3) Coding — Pair programming and collective ownership improve code quality and knowledge sharing. (4) Testing — Test-first development (unit tests before code) catches defects early. [3 marks per activity]
3.1 ATM withdrawal use case? Actor: Customer. Precondition: Card inserted, PIN correct, account has funds. Main flow: (1) Customer selects Withdrawal. (2) Enters amount. (3) System checks balance. (4) System dispenses cash & updates account. (5) Receipt printed. (6) Card returned. Alternate flow: Insufficient funds → decline message. [1.5 marks per clear activity, up to 6 activities = 9 marks]
3.2 Two non-functional requirements for ATM? Any two: (1) Performance — transaction must complete within 3 seconds to avoid timeout. (2) Security — data must be encrypted (TLS/AES); card data not stored after session. (3) Availability — system uptime must be ≥99.9%. (4) Usability — UI must be accessible to users with visual impairments. [3 marks each]
