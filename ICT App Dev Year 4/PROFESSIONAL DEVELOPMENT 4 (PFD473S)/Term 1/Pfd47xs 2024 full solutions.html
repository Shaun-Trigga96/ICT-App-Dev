3.1 — Define Project Management

[4 marks]
Model answer

Project Management is the application of knowledge, skills, tools and techniques to project activities in order to meet project requirements. (PMBOK Guide)

It is accomplished through the application and integration of the five process groups: Initiating, Planning, Executing, Monitoring & Controlling, and Closing.

Alternatively (functional view): project management is the process of guiding a project from beginning through its complete duration to its end using a set of management models — encompassing Planning, Organizing, Controlling, and Terminating.

3.2 — Explain the Fundamental Trade-Off in Project Management

[4 marks]
Model answer — The Iron Triangle

The fundamental trade-off in project management is known as the Triple Constraint or Iron Triangle. Every project is simultaneously constrained by three competing factors:

  • Scope — what work needs to be done; the features and deliverables of the project
  • Time — the schedule; when the project must be completed
  • Cost — the budget; how much money is available

Quality is often added as a fourth central constraint that sits inside the triangle.

The trade-off is this: changing any one constraint forces a change in at least one of the others. For example, if a project manager needs to shorten the timeline (reduce time), they must either reduce scope OR increase cost (hire more people). You cannot change one without affecting the others. The project manager's job is to balance these competing demands while satisfying stakeholders.

3.3 — Four Fayol Principles Applied to a Software Project Team of Five

[12 marks]
Name FOUR principles, define each, and explain how it applies when a project manager leads a team of five on a software development project. Each principle is worth 3 marks (name + definition + application).
Principle 1: Specialisation of Labour (Division of Work)
Definition: Specialising encourages continuous improvement in skills and development of better methods. Work should be divided according to people's strengths and expertise.

Application to software project: The project manager assigns each of the five team members to tasks that match their expertise — for example, one developer handles the front-end, another manages the database, a third is responsible for testing, and so on. Rather than everyone doing all tasks, specialisation increases quality, reduces errors, and improves team efficiency. Each member deepens their skill over the project duration.
Principle 4: Unity of Command
Definition: Each employee should have one and only one boss — receiving instructions from a single supervisor only.

Application to software project: All five team members report exclusively to the project manager. This prevents confusion caused by conflicting instructions from multiple sources. If a developer receives task assignments from both the project manager AND a department head simultaneously, they become confused about which task takes priority. Having a single point of authority ensures clear direction, accountability, and smooth progress. (Note: this principle is violated in matrix organisations where team members report to two managers.)
Principle 5: Unity of Direction
Definition: A single mind generates a single plan, and all team members play their part in that plan.

Application to software project: The project manager creates one cohesive project plan covering all five team members' activities. All team members work towards the same project objective — for example, delivering a working software system by a specific date. Without unity of direction, team members might pursue different interpretations of the goal, wasting effort. The PM's job is to ensure everyone understands the unified objective and their role in achieving it.
Principle 14: Esprit de Corps
Definition: Harmony and cohesion among personnel — building team spirit and a sense of collective identity.

Application to software project: The project manager fosters a positive team culture among the five members — encouraging open communication, celebrating milestones (like a successful sprint review), and resolving interpersonal conflicts quickly. A team that trusts and supports each other collaborates more effectively, shares knowledge willingly, and produces better software. Fayol warned against divide-and-rule tactics, which destroy team morale. A united team is more resilient when facing technical challenges or schedule pressures.
